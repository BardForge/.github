# Метки и этапы BardForge

Скрипт синхронизирует 38 общих меток с английскими именами и русскими описаниями. Для продуктовых репозиториев также настраивает четыре этапа: Audio MVP, Mixer Improvements, Workspace и Future. **В `BardForge/.github` синхронизируются только метки; существующие этапы не изменяются.**

Требования: Python 3.10+, GitHub CLI `gh` с выполненным входом и правами на выбранный репозиторий. Репозиторий выбирается явно из списка: `BardForge/.github`, `BardForge/bardforge`, `BardForge/bardforge-foundry`, `ShinozakiAichi/BardForge-Studio`. Зависимости Python устанавливать не требуется.

## Использование

Запускайте команды из папки скрипта. По умолчанию выполняются только чтение GitHub API и подготовка плана.

```powershell
python manage.py --validate
python -m unittest -v test_manage.py
python manage.py --repo BardForge/bardforge
```

Проверьте полученный `BardForge--bardforge.plan.json`: сопоставления старых меток, назначения задач и этапы. Применение запускается отдельной командой:

```powershell
python manage.py --repo BardForge/bardforge --apply --review BardForge--bardforge.plan.json
```

Перед записью скрипт повторно читает состояние GitHub. Если оно или конфигурация изменились после подготовки плана, нужно сформировать новый план. После применения скрипт проверяет результат через API и сохраняет `*.result.json`. Повторный запуск без `--apply` должен показывать ноль операций.

## Сохранение существующих данных

- Известная старая метка переименовывается на месте, если новое имя ещё свободно: назначения задач и pull request сохраняются.
- Если обе метки уже существуют, новая добавляется к назначениям старой, включая закрытые задачи и pull request. Старые метки и другие назначения остаются; удаления и замены всего списка меток нет.
- Пользовательские метки сохраняются. Архивированные основные метки и неоднозначные названия этапов требуют отдельного рассмотрения.
- Этапы продуктовых репозиториев обновляются без назначения новых сроков, изменения открытого/закрытого состояния или переноса задач. Направления v0.2.0 и v0.3.0 предварительные. Foundry остаётся необязательной интеграцией; её приёмка требует проверки в Foundry и воспроизведения на удалённом клиенте.

Запросы выполняются через `gh api` с JSON во стандартном вводе, без командной оболочки. При ошибке уже выполненные запросы сохраняются в отчёте; новый план позволяет продолжить оставшуюся работу. Общей транзакции для нескольких запросов GitHub нет.

## Состав папки

В репозитории достаточно хранить `manage.py`, `desired-state.json`, `test_manage.py`, этот `README.md` и `.gitignore`. Рекомендуемое расположение: `scripts/github-management/`. Сгенерированные аудиты, планы, отчёты и `__pycache__` не публикуются.

Контракты запросов: [метки GitHub REST API](https://docs.github.com/en/rest/issues/labels), [этапы GitHub REST API](https://docs.github.com/en/rest/issues/milestones). Используется версия API `2026-03-10`.
